# 变量 3.0

3.0 负责变量的规则、独立更新与回滚。当前值是酒馆原生聊天变量，使用原有的变量面板和取值宏。

## 给 RP 展示什么

- `{{xbgetvar::hero.health}}`：读取当前值，支持已有的子路径写法。
- `{{xbvardesc}}`：展示定义里的分组说明和字段含义。
- `{{xbvardesc::character}}`：只展示 `views.character` 涉及的含义。

描述宏包含所选字段相关的规则、动作、触发和约束说明，不包含当前值、提交格式或更新指令。作者在正常启用的世界书条目里按条件选取需要的值和描述，不必整包注入变量。常驻条目可以放角色后；位置与排序按作者的上下文组织选择。

字段含义写在 `access[].description`，更新的时机、证据和填写方式写在可选的 `access[].update`。动作、计算和约束写在定义各自的位置，由更新器直接读取。分开是为了防止 RP 把变量维护要求当成本轮叙事任务。

## 定义与当前值

编辑文件、完整格式和制作流程见 [制作说明](skill/SKILL.md)。定义及函数包只保存在角色卡扩展。每次更新、试算和描述组装都读取卡上已保存的规则；保存或导入后，下次直接使用，不需要再应用。

定义的初始值必须是对象；顶层键对应原生变量根。首次初始化完成后记录受管根，负责这些根及整棵子树，包括后续合法新增的子字段；schema 或规则新增声明不会接管其他独立变量。启用时只补齐缺失根，已有同名值进入规则校验，不重置其他变量。

当前值唯一保存在 `chat_metadata.variables`。3.0 聊天元数据仅保存受管根、结算版本标识、修订与必要检查点；swipe 保存实际可逆差量。预览和组装请求使用临时起点，不发布到聊天。原生变量被修改后，仍在等待的旧提交不能覆盖新起点。

界面中的“导入规则”“导出规则”处理的文件包含 `definition` 与 `functions`，不包含聊天变量和回滚记录。导入先校验、再确认，完整替换规则及函数，不合并、不重置当前变量、不执行动作，也不改其他卡内容。已有编辑草稿保留；如需改新规则，通过 CardFiles refresh 重读整组，旧草稿直接保存会提示冲突。

## 更新结果与恢复

数值显示前后变化，数组显示实际新增、删除、修改的元素，对象显示变化字段。数组混合增删使用 jsondiffpatch 的差量、应用与反向恢复，避免为一个变化记录整个数组。数组匹配按相同内容定位，不要求作者提供 id；两处相同内容之间的对象修改按顺序配对，保留字段级变化。

存档直接使用库的差量格式，结果展示是它的只读投影。库边界对对象字段名统一做可逆编码，隔离库保留的 `_t` 标记；数组下标和字符串内容不改写。普通恢复与跨楼层保留分开：后者只补所需父结构及空位，再由库应用变化。

AI 提交的 `reason`、`old` 和自定义说明按原操作顺序现场展示，不参与执行，也不写入存档。切换聊天或 swipe、编辑、删除、撤销后丢弃；历史展示从已有差量读取，不复活旧说明。

取消正在生成的新 swipe 时，恢复原分支的变量和底部操作。恢复直接使用已有差量，不重新调用 AI，不重跑动作、奖励或触发规则。检查点用于加速可确认的连续回滚。

保留后续楼层而切换旧楼时，后续已经确认的字段继续保留；缺失的父结构按需要恢复，旧楼独有的其他字段撤销。数组路径按位置恢复，必要的空位为 `null`。历史只在起点改变时记录重合成后的实际可逆差量，以保证再切回来、撤销后楼、尾删和重开一致；不会保存完整状态副本或重新执行规则。

历史切换恢复后只读检查 schema 和约束：合法则静默，冲突则展示作者规则和当前字段值，不阻止切换、不自动修正、不重算后文。下一批更新仍按最终结果校验，能消除冲突就接受。恢复结果展示本次真实变化，不用旧回复的结算覆盖它。

恢复没有新的操作前态；检查中需要读取 `before` 的约束留给实际结算校验，不用恢复后的值假冒前态。晚于新操作返回的恢复检查不覆盖新结果。结果说明只使用与该次结算一致的规则版本，不把新规则的说明套在旧结果上。

复制回复不继承结算归属，副本所有 swipe 内复制来的 3.0 记录都会清理；原回复及其他扩展字段保留。归属只在当前聊天内存中跟踪，宿主保存的是清理后的副本。已有正文入口的结算记录在打开聊天时归入模型提交，保留其变量效果和撤销记录，之后重新更新可替换它；聊天正文不改写。

## 必须守住的约束

- 所有入口（按钮、自动、API）提交同一批修改时，使用同一套转换、动作、关联计算和校验；整批任一步失败或取消都不发布。
- 异步提交不能跨聊天、跨 swipe，也不能覆盖已被原生修改的起点；保存未返回时，切 swipe 和尾删仍立即恢复，保存失败只重试保存、不重算。
- 卡上保存的规则是唯一规则源；在途操作不混用新旧规则；规则变更不重置变量，也不接管受管根以外的变量。
- 自定义函数只读声明路径，不能访问宿主、网络或存储；超时或取消后执行环境退出。
- 原生变量写回、宏、面板、结算和重开保留字符串、数字、布尔、null、数组、对象的类型。
