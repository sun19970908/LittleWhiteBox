# 小白X角色卡制作

你在小白助手的角色卡工作区里组织角色设定、世界书与提示词，并按需要制作小白X（LittleWhiteBox）的前端、变量与任务。目标是把用户需要的内容写回当前卡，能继续边用边改。已有卡的无关任务、正则、世界书和玩家数据保留原样。

## 开始工作

通过 CardFiles open 取得当前卡目录，先读与需求有关的已有文件。编辑使用助手原有的 Read、Grep、Write、apply_patch；CardFiles save 只接收要写回的文件路径。本文末尾的文件操作说明给出实际布局。

用户在同一工作区可以看到、编辑和继续修改文件。内容可以分次写回，未完成脚本也能保存；写回不执行脚本或改动聊天变量。运行检查与保存是两件事，检查发现问题就继续修改，不要求用户一次写对。

## 先组织模型会读到什么

新建卡、拆分世界书、调整蓝绿灯或提示词层次时，先读[提示词组织](<references/prompt-organization.md>)。先按其中的内容骨架归位，再决定放在哪个载体、什么时候进入请求、怎样控制先后，以及怎样检查实际展开结果；小白X的变量与前端能力在这个基础上接入。只修按钮或脚本时，直接读对应能力参考。

## 小白X的两条制作原则

**前端是 AI 文本的呈现。** 卡约定一种输出格式，用标签或固定结构把文本块组织好；正则匹配这个文本块，替换成界面。每个回复是一个新楼层，前端随楼层渲染。轻量、中等都从“约定格式 + 正则”开始；循环任务常驻应用只属于重型。

**变量是当前的完整状态。** 小白X变量保存最新的全部状态，删楼、swipe 时自动回到对应位置。前端和模型随时读到最新的全部值，AI 只交变化，不重复输出全部状态。制作时按下文的变量一节选择变量版本。

## 先确定玩家怎样使用这张卡

先读已有开场白、世界书、正则与任务。涉及输出格式、变量通道时，再用已有的酒馆读取工具或用户导入的预设了解：它怎样生成和保存楼层、有没有自己的显示正则、变量变化由谁提交。根据需求确定：玩家看到什么、点击什么、成功后看到什么、失败后怎样继续。需求已明确就按需求实施。

| 前端档位 | 实现 |
| --- | --- |
| 无前端 | 正常文字聊天；需要变量时只做初始化与提示词 |
| 轻量展示 | 约定格式 + 显示正则，替换成酒馆净化后的 HTML（无脚本） |
| 中等交互 | 约定格式 + 显示正则，替换成 HTML 代码块，由小白X渲染为楼层 iframe，可读变量、带脚本与按钮 |
| 重型应用 | 循环任务挂常驻应用，玩家主要在应用里操作；读[重型前端参考](<references/xiaobaix-heavy-ui.md>) |

约定格式时：

- 用卡自己的标签，不依赖预设的标签。预设可能有显示正则先改写文本，也可能在整理历史时剥掉标签；核对预设后再定标签名。
- 格式要能被正则稳定匹配：开闭标签成对、不嵌套同名标签、生成中断时未闭合的文本照常显示。
- 楼层 iframe 在生成结束后才渲染，流式过程中显示的是原文。

图片与前端档位独立：无图、自备素材、运行时绘图或混合均可，见[媒体接口](<references/xiaobaix-capabilities.md#media>)。

## 变量

新卡要用变量时，默认推荐变量 3.0：它有动作、派生值、修正和触发规则，先读 ReadSkill builtin-state3。只需要几个数值由模型按剧情直接增减、没有规则结算的简单变量，用变量 2.0，先读 ReadSkill builtin-state2。维修已有卡时沿用这张卡现在的变量版本；交付时写明所用的变量模式，由玩家在小白X设置里选择。

两个变量技能负责结构、初值、更新规则和前端读写；世界书、开场白、正则与前端仍按本技能组织。依据变量值切换模型看到的描写、或在本轮成功后执行确定动作时，用世界书里的[条件规则与动作 `<varevent>`](<references/xiaobaix-capabilities.md#varevent>)；变量 3.0 里改变状态的后果写进定义的规则与触发，`<varevent>` 的动作只做状态以外的事（如启停世界书条目、调用快捷回复）。

## 在哪里执行代码

| 位置 | 适用寿命 | 读取方式 |
| --- | --- | --- |
| 显示正则 | 随楼层；正文美化 | 经宿主 HTML 净化，无脚本 |
| 楼层 HTML 代码块 | 随楼层；本楼显示与交互 | 同源 iframe；宿主公开 API 从 `window.parent` 访问 |
| 循环任务 `<<taskjs>>` | 后台动作或跨楼层常驻界面 | 运行于酒馆页面，使用 `window`、`document`、`SillyTavern.getContext()`；注入的 `ctx` 是任务日志上下文 |

触发时机、停止条件、iframe 寿命见[能力参考](<references/xiaobaix-capabilities.md>)第 2～4 节。常驻任务重跑先卸载旧实例，登记 `onCleanup`；角色任务离开所属角色时由插件停止。图片、地点表等大块共享数据由任务挂到父页面一份，各楼 iframe 从 `window.parent` 取，取不到时降级；带 iframe 的正则用 `maxDepth: 0` 只给最新一楼，见能力参考第 3.4、4 节。

写前端时先读[样式、脚本作用域与交互验收](<references/xiaobaix-capabilities.md#frontend-validation>)；显示当前变量的面板同时按[变量刷新](<references/xiaobaix-capabilities.md#state-panel-refresh>)接线。自动后台任务与玩家按钮的区别见同文第 2.1 节。

## 写入哪些卡工程产物

角色任务、正则、世界书与卡字段按本文末尾的文件布局编辑，写回由 CardFiles 完成。更新已有任务沿用原 ID。工作区中的辅助笔记不是运行时可访问的网址；前端代码要放进可写回的正则替换内容或完整任务脚本。

交付包括本次实际需要的格式规则、正则、HTML、任务与变量初始化，以及启用条件（所用的变量模式、循环任务开关、允许卡内正则），不替玩家改全局设置。

## 怎样证明做完了

- 先检查 JSON、JS 与正则的语法；正则用真实楼层文本（含预设保存的格式）核对匹配与替换。助手的 RunJavaScriptApi 在当前酒馆页面里执行普通异步 JavaScript，可读写真实页面和聊天状态，会改动状态的代码按权限模式确认；它不提供 Node、文件系统或命令行。只报告实际执行过的检查。
- 变量验证初始化、模型提示词里宏的实际展开结果、变化量写入、swipe/删楼后的显示值。
- 常驻界面验证重复挂载、停止、切聊天；重型卡验证桌面/手机与无图状态。
- 前端按[交互验收](<references/xiaobaix-capabilities.md#frontend-validation>)检查真实计算样式、点击与重绘后的状态；静态截图和无控制台错误不能代替操作。
- 写回回执不等于任务已经运行，也不等于真实酒馆联调通过。已有工具能检查的先检查；运行会改变玩家状态时，在隔离聊天验证，交付说明实际检查到哪一步。
- 确认可复用的故障原因后，可记入助手工作记录；本技能随插件发布，不是用户可写的 skill 文件。尚未查实的猜测不写成接口事实。
