# 重型前端：终端与操作驱动应用

只有玩家主要在前端完成操作时才读本篇。多页面桌面、手机式应用、终端都属于重型；普通状态栏不需要常驻应用。聊天是否持续推进、是否自动生成文字或图片，由卡的玩法决定。

## 先定操作旅程

玩家从哪里打开 → 看见本轮什么内容 → 能做哪些操作 → 操作改变什么 → 成功或失败怎样反馈 → 怎样回到聊天。

根据这条旅程再安排页面、变量与任务，而不是先套一个带抽卡、商店或行动限制的通用模板。

| 部分 | 制作决定 |
| --- | --- |
| 名称、地点、行动、素材键 | 按卡设定组织，未使用的玩法不带入 |
| 挂载与卸载 | 一个角色任务负责常驻；DOM ID、全局接口名用卡专属名称 |
| 界面偏好 | 展开状态、标签页等只记普通界面变量 |
| 剧情与玩法状态 | 从变量 2.0 受管根读取，写入与回执见变量指南 |
| 操作与展示 | 按需求写页面、按钮与失败反馈，不强制带事件锁 |

任务执行位置、重跑和资源清理见[能力参考](<xiaobaix-capabilities.md>)第 2 节。写回使用 CardFiles 的任务设置与完整脚本，不需要本地任务打包器。

## 与聊天交互

- 全屏界面遮住聊天时，要能在应用内阅读本轮正文，或随时退出回到聊天。局部小窗不必复制一份阅读器。
- “填入输入框”和“直接发送”是两个动作。保留玩家原有草稿，或明确显示将发送的内容，避免无提示覆盖。
- 操作不推进聊天时可直接结算；推进回合时可将结算随玩家消息发出。入口、回执、归属楼层见[前端结算](<xiaobaix-game-state.md#frontend-settlement>)。
- 文字生成、绘图是独立服务请求，不等于聊天消息已保存，也不等于数值已经提交；分别处理结果。
- 显示的价格、概率、稀有度和发给 AI 的叙事行动可以分开；世界观本来就有系统或商店时按设定保留。

## 原卡只有文本状态栏时

读取最近消息原文中卡自有的状态标签。显示正则可以把状态块替换成入口，并把完整匹配作为隐藏容器保留；此规则只改变显示，不改变模型输入。宿主会移除内联事件并给普通类名加 `custom-` 前缀，点击由任务里的事件委托处理，读取隐藏原文用 `textContent`。

变量 2.0 卡直接读当前状态，不要求 AI 重复输出整份状态栏。`<state>` 隐藏规则是请求记录的显示处理，不能与普通状态栏入口混为一谈。

## 无图与手机布局

- 没有素材时正文与操作区正常铺开，图片区可以收起；画面热点可配文字按钮。
- 内部 flex 滚动区设置 `min-height: 0`；手机全屏用 `100dvh` 适配地址栏。
- 重绘状态时保留阅读位置和界面选择；只在正文变化时替换正文。
- 动态文本用 `textContent` 或转义后放进 HTML。背景直接换图，过渡可用遮罩透明度，不靠大 Data URL 的 `background-image` 动画。
- 宿主样式、脚本作用域和键盘操作见[交互验收](<xiaobaix-capabilities.md#frontend-validation>)。

## 可选的游戏规则

只有玩法确实要求限制行动时才设置限制，并告诉玩家原因与下一步可做什么；这不是使用小白X前端的门禁。

需要随机掉落时，由前端按卡的概率规则抽样并保存结果，AI 描写已确定的结果。保底、次数、物品一起记账，重复渲染不重新抽样。批量操作可能部分成功，不能先宣布“购买完成”再忽略回执。不可分割的交换，先验证条件，再对符合模板的最小完整对象一次 `set`，或明确设计结算规则；不把批量操作当事务。

## 自备素材与运行时绘图

自备图片使用酒馆页面实际能访问的 URL，或用户提供的 Data URL。工作区文件路径不是图片服务器地址。本地素材目录、Node 打包命令、离线预览文件都不是小白助手里的运行能力。

图片、地点表等大块共享数据由常驻任务保留一份，各楼 iframe 从父页面读取，不往每楼正则代码块里重复塞整份。暂时读不到素材时保留文字与操作区。任务停用时清理挂载的接口和 Blob URL。

动态绘图按[媒体接口](<xiaobaix-capabilities.md#media>)接入，取消、部分结果与生成费用分别处理。要让图片刷新后留在原位置，按同文保存结果的章节处理，不能把进图库当成卡内持久化。

## 验收

在隔离聊天验证：挂载两次只有一套界面；停用目标任务后清理；切角色卸载；同角色换聊天读新存档。不要为验收停止全部任务，打断用户其他卡或工具。

桌面与手机分别检查正文滚动、标签页、图片展开、关闭与重新打开；操作后再触发状态刷新，检查界面选择没有丢失。静态预览不能证明真实生成服务或历史恢复。
