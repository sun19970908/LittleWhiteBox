# 小白 OS UI 分批改造

## 范围与方向

清透、鲜活的掌上 OS：统一正常阅读尺度与操作习惯，应用按自身活动建立布局，不统一套仿旧纸张、灰绿和大圆卡。

- 当前 11 个桌面图标统一重整：各 APP 保留明确色彩与对象轮廓，减少细碎材质和厚重阴影。API、四次元壁图标同批更新，内部不做专项重设计。
- API、四次元壁内部不做专项重设计，可自然继承全局基础样式变化。
- 保留现有桌面布局与壁纸，不引入旧皮肤开关或样式兼容分支。
- 每批包含主要流程、详情、确认、空状态、加载与失败状态，不把收尾留到最后一批。

## 批次

| 批次 | 范围 | 交付重点 |
| --- | --- | --- |
| 1 | 基础规范、八个图标、任务 | 本地 SVG 图标；统一字体、圆角、阴影与动效尺度；任务接取和发布两条完整线路 |
| 2 | 钱包、银行 | 余额与账单、资产与存单、持仓与到期领取 |
| 3 | 商店 | 物品图形、货架、详情、购买与背包 |
| 4 | 地图 | 世界图生成语义与地图优先 UI；未到访目的地、区域探索、搜索定位与场景图 |
| 5 | 游戏 | 大厅、入席与筹码、三个玩法的操作和揭晓、结算与继续 |

## 第一批结构

- Shell 提供基础字体、尺度变量、桌面展示与既有加载入口。
- 各 APP 的 `ui/icon.svg` 拥有其图标，Shell catalog 引用静态资源，不依赖 APP Host 可用性。
- Tasks 自有 UI 拥有卡片、详情、候选人、发布表单、确认弹窗及展示分类；不建设通用业务 UI 框架。
- `TasksPresentation` 和现有详情读取仍是展示事实来源；不复制业务状态到新的持久实体。
- 页面选择、确认动作、草稿、正在读取的详情只活在当前运行内。
- 不增加外部 API、字体服务、素材服务或运行依赖；不改 Kernel、存储、资金、领域命令和 Prompt。
- 废弃的任务模板、样式、图标路径数据直接替换；不留并行旧 UI。

任务内部的当前页面契约见 [Tasks 设计第 12 节](./tasks-app-target-design.md#12-ui-与本地文案)。

## 第二批结构

- Wallet 自有 UI 展示钱夹余额、按日期分组的账单、方向筛选和完整只读回执；Economy 投影仍是唯一事实来源。
- Bank 自有 UI 展示本金总览、平整产品列表、持有资产、兑付记录和原生模态确认；黑白底、蓝色操作点缀，不保留装饰保险柜。资金操作沿用现有 endpoint、CAS、actionId 与原子保存。
- 页面、筛选、展开记录、选中账目、输入金额与待确认动作均为临时态；不增加持久字段或外部依赖。
- 原有 Wallet「核实保存结果」按钮缺少 Host 处理，本批通过 Wallet 模块安装入口接入既有 Kernel 文件恢复能力，不扩展 Economy 只读权限、不改变提交规则。
- 删除路径仍为各 APP 目录与注册；新增 UI 不拥有需清理的数据。只需兼容现行 Host 协议、数据投影与浏览器，不保留旧皮肤或旧模板。
- 最少验证为现有资金/Host 测试、Wallet 核实入口的真实未确认保存回归、类型/lint/构建，以及浏览器操作和深浅多尺寸检查。

## 第三批结构

- Shop 自有 UI 采用清亮底色、珊瑚色操作和有独立形态的商品陈列；商品图形使用本地 SVG，不使用外部素材或字体服务。当前页面契约见 Shop 设计文档，不再沿用奶油黄铜旧皮肤。
- 主导航为「逛店 / 背包 / 生效中」。货架支持本地分类与搜索，商品详情完整展示作用期限、价格、持有量与使用要求；购买和使用保持两步。
- 商品与效果始终读取 `ShopClientState`。详情和确认框只保存商品 / 效果 ID，状态推送后读取最新投影；不复制库存、余额或效果状态。
- 页面、分类、搜索、详情选择、返回滚动位置、输入参数和操作成功提示均为运行内状态，不新增持久化实体。
- 购买、激活、关闭、保存核实继续走现有 Host 入口和 actionId / CAS；不改 Shop/Economy 事务、目录合同、Prompt、收据与效果交付机制。
- UI 位于 `apps/shop/ui`，注册与加载入口不变；删除本批 UI 不涉及数据清理，不留下旧皮肤。兼容对象只包括现行 Host 投影、浏览器与 WebView。
- 最少验证：现有 Shop/资金/Host 测试、类型/lint/构建；浏览器检查购买与使用分离、背包变化、重复使用、手动/永久/有限效果、失败及未确认保存、深浅主题与多尺寸。

## 第四批结构

- Map 自有领域/Prompt/UI 负责世界探索；世界图依作者设定建立，留白合理补全，场景图只负责具体地点内部。
- 地图仍唯一存于当前聊天 `map` 分区。地点新增可选稳定位置/地貌，随地点生命周期；浏览区域、搜索、选择、缩放与弹层均为临时态。
- 沿用现有世界图 → 主剧情的 800 字安全摘要，无玩家位置也能注入已有世界。世界书输入仍是 Host 捕获的触发片段，不扩为扫描全书。
- 公共 maintenance 不再硬编码所有领域禁止创造；Map 自己区分世界创造/剧情事实，Tasks 明确禁止把背景或补充地图作为任务进展证据。
- UI 采用浅色纸地图/夜间绿，SVG 地图、本地线图标与共享场景字体，无新外部依赖、定位权限、存储实体或注册入口。
- 删除旧层级树布局；功能删除仍清理 Map 目录、注册与 map 分区。现行 Host/Provider/浏览器为兼容边界，不保留旧 UI。
- 必要验证覆盖未到访地点保存、坐标/地貌读写与非法输入、人物位置不变、主剧情注入、稳定区域布局，以及浏览器搜索/区域/定位/场景/双指/主题/保存风险状态。

## 第五批结构

- Game 自有目录和玩法房间。大厅只找游戏、浏览分类、继续已有局；入席、动作、揭晓和记录详情由各玩法模块拥有，总页面无三款游戏分支。
- 大厅直接展示游戏，不以海报、口号占首屏；手机两列，宽屏三列。返回保留搜索/分类/滚动，清晰白底与中性深色对应青绿骰桌、紫色牌桌、蓝色阶梯。
- 大话骰用人话叫数和等量骰面；翻牌寻金用牌背、金币和炸弹；步步登高用五层阶梯与三条路。公共组件仅覆盖已有多个消费者的入席与结算。
- 状态与余额唯一来自现行 Host；目录筛选、筹码草稿、动画、重试与结算交接均为运行内状态，不增加持久字段、规则引擎或外部依赖。
- 保留 CAS / actionId / 保存确认和聊天隔离。保存与动画完成之前不提前展示结果或余额；再玩一局不自动下注。
- 规则、赔率、资金协议、数据格式、APP 注册及 API / 四次元壁内部不变。清理旧游戏大页面、重复分支与无消费者弹窗；删除路径仍由 Game 目录、领域、注册与现有分区拥有。
- 验收覆盖三玩法完整流程、继续与另局互斥、30 项目录浏览、合法叫数、金币翻牌与阶梯判定、深浅多尺寸、减少动效、超时重试及保存核实。详见 [游戏终态设计](./game-app-target-design.md#7-第五批-ui-与扩展边界)。

## 验收边界

本轮补充信息页文案与排版清理：去列表副标题、页脚、线程身份重复说明和空态寒暄；保留实际通讯内容、媒体与所有错误恢复入口。11 个图标仍由各 APP 的本地 SVG 拥有，Shell 只减轻图标投影，不改变用户已认可的桌面玻璃布局与壁纸。

- 自动检查：现有领域 / Host 契约、任务双线路显示回归、类型检查、lint、构建、diff 检查。
- 浏览器：手机窄屏和桌面设备框、深浅主题、键盘与减少动效；任务双线路；钱包筛选、分页与回执；银行存入、申购、提前支取、到期领取、记录分页、金额校验及保存失败/核实路径；地图未到访地点、搜索、区域深入与返回、场景、定位只读、拖拽/双指、空图与保存风险；商店筛选与详情返回、购买与使用分离、背包和效果变化、重复使用、永久/手动/有限效果、保存失败与核实、生成中操作限制。
- 本地 UI 验收使用隔离的 Host 模拟数据，不读写真实聊天和钱包；它验证前端交互，不代替真实 SillyTavern / Provider 验收。
- 截图与本地验收模拟页放在忽略的 `output/playwright/`，不进入运行产物。
