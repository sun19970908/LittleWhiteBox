# 剧情总结

聊得久了，AI 会忘记前面发生过的事。剧情总结会把聊天整理成剧情事件、人物关系和世界状态，每次生成时把这些记忆交给 AI，让它在长对话里也记得前情。开启向量检索后，它还能在回复前找回和当前话题最相关的原文片段。

## 启用功能

1. **扩展设置 → 小白X → 数据互动 → 勾选 `剧情总结`**（默认开启）。
2. 打开一个聊天，点任意楼层消息上的 `剧情总结` 按钮（折线图图标）打开面板。按钮被收进 X 按钮时，见 [X 按钮](tools.md#x-按钮收纳消息按钮)。
3. 默认用酒馆当前的 API 生成总结。想换模型，在面板 `设置` → `模型连接` 里选预设，见 [API 预设](api-presets.md)。

总开关管全部聊天。只想在某个聊天里停用，打开面板 `设置` → `总结规则`，取消勾选 `此聊天` 下的 `启用剧情总结`。停用后这个聊天不再自动总结、不再注入记忆，已有资料保留，面板会显示 `当前聊天已停用`。

## 三步上手

1. **正常聊天**，先攒二十楼左右的对话。
2. **点 `总结`**：面板右上角的按钮。总结只处理还没总结过的楼层，完成后面板提示 `总结完成，已保存至 N 楼`。运行中按钮变成 `停止`，可以随时停下。
3. **按需开启自动总结**：在 `设置` → `总结规则` 勾选 `启用自动总结`，之后每攒够一定楼数自动总结一次。

建议第一次先手动点一次，看看效果再决定是否开自动总结。

## 面板

面板顶部显示 `已总结 N 楼` 和 `待总结 N 楼`，右上角有 `助手`、`总结`，以及切换主题、`设置`、`数据管理`、关闭四个图标。

| 标签 | 内容 |
| --- | --- |
| `剧情` | `全部剧情` 时间线，可切换 `最新在前`、打开 `分页`；左侧 `剧情索引` 和 `核心关键词` |
| `人物` | `人物关系` 图（可 `全屏查看`）、`人物档案`、`称呼与别名` |
| `世界` | `世界状态`：仍然成立的设定和事实 |

顶部搜索框可以按关键词筛选当前标签的内容。点任意事件或人物可以看详情。

### 手动修改记忆

每个区块都有 `编辑`（关键词、剧情、人物关系、人物档案、别名、世界状态）。改完点 `保存` 立即生效，之后的总结会在你修改过的版本上继续。

## 设置

点面板右上角的 `设置`（齿轮图标）。左侧标签：`总结规则`、`模型连接`、`向量召回`、`提示词`、`外观`。改完点底部 `保存设置`，不想要了点 `还原修改`。有未保存的修改时离开会提示 `有未保存的修改`。

标签上标着 `此聊天` 的只影响当前聊天，标着 `全局` 的影响所有聊天。

### 总结规则

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| `启用剧情总结`（此聊天） | 开启 | 即时生效，不用点保存 |
| `启用自动总结` | 关闭 | 勾选后才出现下面三项 |
| `自动总结间隔（楼）` | 20 | 1～30。待总结楼层达到这个数时触发 |
| `触发时机` | `用户发送前` | 也可选 `AI 回复后` |
| `总结完成提醒` | 关闭 | 每次总结完成后弹出 `剧情总结完成：更新至 #N 楼（新增 M 个事件）` |
| `单次最大总结（楼）` | 100 | 25 / 50 / 100 / 150 / 200。一次最多总结多少楼 |
| `最近几楼暂不总结` | 2 | 0～30。最新的几楼先不总结，手动和自动都按这个规则；0 表示总结到最新 |
| `隐藏已总结楼层` | 开启 | 已总结的旧楼层不再发给 AI，靠记忆代替，省 token |
| `保留最近楼层` | 6 | 0～50。隐藏时仍保留最近几楼原文 |
| `按向量进度隐藏` | 开启 | 开：按向量处理的最新进度隐藏；关：按剧情总结的最新进度隐藏。只有开启向量检索时可改 |
| `注入角色` | `System` | 记忆以哪种角色的消息发给 AI |
| `强制插入到聊天最后（插件冲突用）` | 关闭 | 和其他插件冲突时才用。勾选后可设 `头部包裹词`、`尾部包裹词` |
| `文本过滤规则` | 3 条 | 总结前去掉干扰内容，默认过滤思考标签和代码块。可 `添加` 规则 |

自动总结失败会自动重试，最多 3 次，进度显示为 `自动总结 1/3：…`。

### 模型连接

选择总结用的 API 预设，见 [API 预设](api-presets.md)。

### 向量召回

不开向量也能用：AI 能看到剧情摘要，但看不到原文细节。开启后，每次回复前会从全部历史里找回和当前话题最相关的原文片段一起交给 AI。故事越长越值得开。

1. 勾选 `启用向量检索`。
2. 依次点 `锚点提取 ›`、`向量模型 ›`、`重排模型 ›`，填 `API URL`、`API KEY` 和模型名，点 `测试` 确认能连上。三处默认都是硅基流动（`https://api.siliconflow.cn/v1`），默认模型分别是 `Qwen/Qwen3-8B`、`BAAI/bge-m3`、`BAAI/bge-reranker-v2-m3`。
3. 在 `记忆锚点` 点 `生成/补齐`，从对话中提取锚点文本。首次较慢，已成功的楼层不会重复生成。
4. 在 `向量数据` 点 `补齐缺漏`。

之后新消息会自动处理。

| 设置 / 按钮 | 说明 |
| --- | --- |
| `召回超时（秒）` | 默认 30。回复前找记忆最多等多久 |
| `L0 并发数` | 锚点提取的并发数，默认 10，按 API 限额调整 |
| `请求超时重试（秒）`（向量模型） | 默认 6 |
| `请求超时（秒）`（重排模型） | 默认 15，仍受 `召回超时` 限制 |
| `补齐缺漏` | 只补缺少的向量，不重算已有的 |
| `完整重建` | 全部向量重新生成，更换向量模型后使用。不会重新提取锚点 |
| `清空` | 清除锚点或向量。清除后可再点 `生成/补齐` 或 `补齐缺漏` 恢复 |
| `召回记录` | 查看最近一次回复前找回了哪些记忆 |

`向量数据` 下方会显示向量状态。提示 `向量引擎/模型已变更` 等问题时，按提示执行 `完整重建` 或 `补齐缺漏`。

### 提示词

| 设置 | 说明 |
| --- | --- |
| `写作要求` | 总结时的写作要求。留空使用内置版本并随插件更新；自定义后保留你的版本。`恢复默认` 清回内置 |
| `记忆注入提示词` | 记忆发给 AI 时的包装文字。必须保留 `{$剧情记忆}` 占位符，它会被替换成实际记忆 |
| `完整总结提示词预览 · 只读` | 查看总结时实际发送的提示词 |

### 外观

`界面主题`：`默认主题 · 亮色` / `默认主题 · 暗色` / `Neo主题 · 亮色` / `Neo主题 · 暗色`，只对这台设备生效。

## 总结助手与自动维护

点面板右上角 `助手`，可以查看 `维护记录`，或点 `与助手聊天` 让 `总结助手` 帮你查记忆、改记忆（例如“把第三章里的称呼改正”）。

- `自动维护记忆`（所有聊天，默认关闭）：开启后，从下一次总结开始，助手会自动检查和修正记忆，成果出现在 `维护记录` 里，每条修改都能看 `修改前` / `修改后` 和 `查看原文`。
- 助手使用共享的 Agent API，在小白X 任意 Agent 功能里设置过就不用重复设置，例如 [小白 OS](xiaobai-os.md) 的「Agent API」。没设置时会提示 `请先在 Agent API 中设置模型和服务地址。`
- 和助手的对话关窗不丢；切换或重新加载聊天后清空。已保存的记忆修改不受影响。

## 数据管理

点面板右上角 `数据管理`，左侧标签：`导入与导出`、`服务器备份`、`清理与回退`、`使用说明`。

### 记忆包

记忆包用来保存或转移当前聊天的总结内容，不是聊天记录或完整回滚历史的备份。在 `导入与导出` 的 `记忆包` 里操作。

**导出**：点 `导出记忆包`，下载一个 JSON 文件，包含关键词、事件、主要人物、角色别名、人物档案和世界状态。不包含原聊天的楼层归属、锚点、向量和维护记录。

**导入**：

1. 打开要导入的目标聊天。
2. 点 `导入记忆包`，选择文件。
3. 确认 `覆盖导入记忆包`：它会替换当前聊天的总结资料，并清空锚点和向量，聊天记录不会删除。没有总结过的聊天也可以导入。
4. 看到 `导入成功：N 条事件，M 条世界状态。…` 即完成。

导入后：

- 以目标聊天当前的最后一楼为新的总结起点，不恢复原聊天的维护进度，也不能回退到被覆盖的总结。要保留当前的总结，先导出一份。
- 锚点和向量已清空，需要时到 `向量召回` 里重新 `生成/补齐` 和 `补齐缺漏`。

导入失败时原有记忆不会被替换：

| 提示 | 处理 |
| --- | --- |
| `仅支持通过"导出记忆包"生成的文件；…` | 只能导入本功能导出的记忆包 |
| `文件不是有效的 JSON 记忆包` / `记忆包内容为空` | 文件损坏或选错，重新选择 |
| `无法读取文件，请重新选择` | 重新选择文件 |
| `请等待当前总结/向量任务结束` | 等总结或向量任务结束后再导入 |
| `聊天已切换，已取消导入` | 导入过程中切换了聊天，回到目标聊天重新导入 |
| `请先打开聊天` | 先打开目标聊天 |

### 向量文件与服务器备份

向量文件只搬运当前聊天的向量，不是记忆备份，换设备时可以省去重新生成。

- `导入与导出` → `向量文件`：`导出向量数据` / `导入向量数据`。
- `服务器备份`：`☁️ 备份向量到服务器`、`☁️ 从服务器恢复向量`、`☁️ 管理服务器向量备份`（可删除旧备份）。

向量文件只能导入回**原来那个聊天**，并且聊天正文、锚点和文本过滤规则要和导出时一致，否则会被拒绝；不能拿来给换了卡的新聊天用。导入失败时当前向量不变。

### 清理与回退

| 按钮 | 作用 |
| --- | --- |
| `回退上一次总结` | 撤销最近一次总结，聊天记录保留。你手动改过的内容和它冲突时不会回退 |
| `清空总结资料` | 删除此聊天的总结、关键词和人物关系，不删除聊天记录，不能撤销 |

总结或向量任务运行中时，这两个按钮暂时不可用。

## 删除楼层与重新生成

删除消息、切换回复（swipe）、编辑消息后，总结、锚点和向量会自动跟着同步，不需要手动处理。删除已总结过的楼层时，面板可能显示 `再删1条将回滚`：再删一条，最近一次总结就会回退。

## 失败时会看到什么

| 提示 | 原因与处理 |
| --- | --- |
| `总结失败` + `模型没有返回总结内容。` | 模型回复为空，换模型或稍后重试 |
| `模型返回的内容不是有效的 JSON，无法读取总结。` | 模型没按格式输出，重试或换更强的模型 |
| `自动总结失败（已尝试 3 次）：…` | 自动总结连续失败，点 `总结` 手动重试 |
| `对话或总结内容已变化，请重新总结。` | 总结期间聊天被改动，重新点 `总结` |
| `暂时无法确认总结是否保存：…` | 点 `总结` 重新确认保存结果 |
| `总结已保存，但后续处理失败：…` | 总结本身已保存，按后面的原因处理向量等问题 |
| `记忆召回失败，本次生成已停止。…` | 向量服务出错，按提示检查 Key、额度和网络后重新发送 |
| `记忆设置已变更，本次生成已停止，请重新发送。` | 生成时改了设置，重新发送 |
| `请先配置 Embedding API Key，再点击"补齐缺漏"继续。` 等 | 向量配置问题，按提示补全后点对应按钮继续 |
| `剧情总结未能完成启动，请刷新页面重试；…` | 刷新页面；仍失败请带上控制台错误反馈 |

总结和找记忆时酒馆底部会显示进度提示，含义见 [生成状态追踪](tools.md#生成状态追踪)。

## 常见问题

### 总结用的是哪个 API？

默认用酒馆当前连接。要单独指定，在 `设置` → `模型连接` 里选预设。

### 换角色、换聊天要重新操作吗？

不用。总结和向量按聊天分别保存，切换聊天会自动载入对应的数据。

### 怎么知道 AI 有没有用上记忆？

打开 `向量召回` 里的 `召回记录`，查看最近一次找回的内容。

### 总结结果不准确怎么办？

点对应区块的 `编辑` 直接修改；也可以让 `助手` 帮你改。

### 想在别的聊天里继续这段记忆

在原聊天 `导出记忆包`，到新聊天 `导入记忆包`。向量需要在新聊天里重新生成。
