# 变量系统

小白X 的变量系统帮你在聊天里记住剧情状态：血量、金币、好感度、背包、任务进度……并让 AI 读得到、改得对。本页讲所有模式共用的部分：怎么选模式、怎么用变量面板查看和修改、读写变量的命令和宏，以及按变量切换世界书内容的条件规则。

## 启用功能

**扩展设置 → 小白X → 数据互动 → 变量控制**

| 设置项 | 作用 | 默认 |
| --- | --- | --- |
| `变量管理` | 让插件按所选模式自动处理变量 | 开 |
| 模式下拉框 | `1.0 (plot-log)`、`2.0 (state)`、`3.0 · 卡规则与结算`，三选一 | 新安装为 `3.0 · 卡规则与结算`；已有用户保持原选择 |
| `变量更新` 按钮 | 打开当前模式的更新设置；只在 2.0、3.0 模式下显示 | — |
| `变量面板` | 在消息上加一个查看、编辑变量的按钮 | 关 |

切换模式后右上角会提示“变量系统已切换为 2.0”之类的文字，之后的消息按新模式处理。

`/xbgetvar` 等命令、`{{xbgetvar::…}}` 宏和条件规则编辑器只要小白X总开关打开就能用，不受上面几个勾选框影响。

## 选 2.0 还是 3.0

三种模式里，变量都存在酒馆原生的聊天变量里，跟着聊天保存。区别在于“谁来改、怎么改”：

| | 1.0 (plot-log) | 2.0 (state) | 3.0 · 卡规则与结算 |
| --- | --- | --- | --- |
| 谁改变量 | AI 在正文里写 `<plot-log>` 块 | AI 在正文里写 `<state>` 块，或另一个模型在回复后更新 | 更新模型提交“发生了什么”，插件按卡上的规则结算 |
| 适合 | 早期按 plot-log 写的卡 | 状态不太复杂、愿意自己写模板和提示词的卡 | 有商店、装备、战斗等多步结算，或需要卡片面板按钮的玩法卡 |
| 写错了 | 被规则挡下的修改不生效 | 类型、字段、范围有模板把关，错的被挡下或修正 | 整批检查，一处不通过整批不生效 |
| 删消息、切 swipe | 回滚到上一楼的快照 | 按每楼记录恢复 | 按每个回复版本的记录恢复 |
| 制作 | 手写 | 手写，或让小白助手帮忙 | 推荐让小白助手全程陪你做 |

怎么选：

- **玩一张现成的卡**：看卡作者的说明，选它要求的模式。选错模式，卡里的变量块不会被执行。
- **自己做卡，状态就是几组数字和列表**：选 2.0，读[变量 2.0](variables-v2.md)。
- **自己做卡，玩法有很多“如果……就……”**：选 3.0，读[变量 3.0](variables-v3.md)。

### 1.0 的写法

1.0 只在仍在使用 plot-log 的老卡上需要。AI 在回复里写一个 `<plot-log>` 块，顶层写操作名，下面按缩进写路径和值：

```text
<plot-log>
set:
  人物状态:
    地点: 森林
bump:
  人物状态:
    金币: -5
push:
  背包: 回血药
del:
  - 临时状态.中毒
</plot-log>
```

| 操作 | 也可以写成 | 作用 |
| --- | --- | --- |
| `set` | `记下`、`记录`、`录入`、`record` | 设置值 |
| `push` | `添入`、`增录`、`追加`、`append` | 往列表里追加 |
| `bump` | `推移`、`变更`、`调整`、`adjust` | 数字加减 |
| `del` | `遗忘`、`抹去`、`删除`、`erase` | 删除 |

1.0 不会处理 `<state>`；2.0、3.0 不会处理 `<plot-log>`。

## 变量面板

变量面板让你直接看到当前聊天里有哪些变量，并且手动改。

### 打开面板

1. 勾选 **扩展设置 → 小白X → 数据互动 → 变量控制 → `变量面板`**。
2. 每条消息的按钮区会多出一个数据库图标（`变量面板`）。如果你的消息按钮被小白X收进了折叠菜单，就到折叠菜单里找。
3. 点它打开面板。

### 面板里有什么

面板分两块：

| 分区 | 内容 |
| --- | --- |
| 本地变量 | 当前聊天的变量，换个聊天就是另一套 |
| 全局变量 | 所有聊天共用的变量 |

每块顶部有一排按钮：

| 按钮 | 作用 |
| --- | --- |
| 导入变量 | 选一个 `.json` 文件，把里面的变量逐个写进来；同名变量会被覆盖 |
| 导出变量 | 把这一块的变量下载成 `.json` 文件 |
| 添加变量 | 填“名称”和“值”，点 `保存`。值可以写 JSON，例如 `{"金币": 10}` |
| 展开/折叠所有 | 一次展开或收起所有对象 |
| 清除所有变量 | 确认后删掉这一块的全部变量 |

下面的搜索框按名称和值过滤。点一个变量展开它的子项。每一项都有这几个按钮：

| 按钮 | 作用 |
| --- | --- |
| 编辑 | 改名称或值 |
| 添加子变量 | 在这个对象下面加一项 |
| 复制 | 单击复制变量路径（如 `人物状态.金币`）；长按复制读取它的宏：顶层变量是 `{{getvar::人物状态}}`，子项是 `{{xbgetvar::人物状态.金币}}` |
| 删除 | 确认后删掉这一项 |

全局变量长按复制的是 `{{getglobalvar::名称}}`，只能读整个顶层变量；在子项上长按会提示已复制顶层变量。

带盾牌、结构、标尺小图标的项设了规则（只读、结构锁、范围等），鼠标移到图标上可看具体规则。

### 保存状态

每次修改后，分区顶部会显示“保存中…”，然后是“变量已保存”。保存失败时显示“保存失败，修改仍保留在当前页面”和原因，旁边有 `重试保存` 按钮——点它再存一次，不用重新改。

如果你改完马上切了聊天，结果会改用右上角提示告诉你存到了哪个聊天，或者哪个聊天保存失败。

### 注意

- 在面板里改值，等于直接改数据：不经过 2.0 的模板检查、不进楼层记录，也不会执行 3.0 的动作和奖励。
- 值以 `{` 或 `[` 开头时按 JSON 存；JSON 写错会提示错误，不会保存。

## 读写变量的命令

酒馆自带的 `/getvar`、`/setvar` 只能整体读写一个变量。小白X 的命令支持用路径直接读写变量里面的某一项。可以在聊天输入框、快速回复、[循环任务](tasks.md)里使用。

路径写法：

- 用点分层：`人物状态.金币`
- 列表用方括号写下标：`背包[0]`、`队伍[1].名字`
- 键名里有点或特殊字符时，用引号括起来：`物品["红.药水"]`；`["0"]` 表示名为 `0` 的键，`[0]` 表示第 0 项

| 命令 | 作用 | 例子 |
| --- | --- | --- |
| `/xbgetvar 路径` | 读取值并返回；对象和列表返回 JSON | `/xbgetvar 人物状态.金币 \| /echo {{pipe}}` |
| `/xbsetvar 路径 值` | 设置值 | `/xbsetvar 人物状态.金币 100` |
| `/xbaddvar 路径 数值` | 两边都是数字就相加，否则拼接成文字；返回新值 | `/xbaddvar 人物状态.金币 -5` |
| `/xbdelvar 路径` | 删除这一项 | `/xbdelvar 人物状态.临时buff` |
| `/xbpushvar 路径 值` | 往列表末尾追加，返回新长度；原来不是列表会先包成列表 | `/xbpushvar 背包 苹果` |

补充说明：

- 路径也可以用 `key=` 写：`/xbsetvar key=人物状态.金币 100`。
- 值写成 `true`、`false`、`null`、数字或 JSON 时，会按对应类型存。
- 读不到的路径返回空字符串，不报错。命令被拒绝或失败时也只是没有效果，**不会弹提示**——没生效时用 `/xbgetvar` 读回来确认。
- 2.0、3.0 管理的变量请按各自页面的方式修改。用这些命令直接改，不会进入楼层记录，删消息、切 swipe 时无法恢复。

### 勾选“变量管理”后，命令会受规则限制

`变量管理` 默认是勾选的。勾选时，这些命令会先经过变量规则检查（无论选的是哪个模式），被拒绝的修改直接不生效。没有设过规则的变量，默认只允许：

- 新建或改写**顶层**变量，例如 `/xbsetvar 金币 10`；
- 改写**已经存在**的子项，例如 `人物状态.金币` 已经有值时改它。

另外，一个位置第一次写入后类型就固定了：`金币` 存过数字，之后再写文字会被拒绝。

下面这些默认会被拒绝，要先在上层加规则放开：

| 想做的事 | 需要的规则 |
| --- | --- |
| 给对象新增子项（如 `人物状态` 里原来没有 `地点`） | 在 `人物状态` 上加 `$ext` 或 `$free` |
| 删除对象里的子项 | 在对象上加 `$prune` 或 `$free` |
| 往已有的列表追加 | 在列表上加 `$grow` 或 `$list` |
| 删除列表里的项 | 在列表上加 `$shrink` 或 `$list` |
| 删除整个顶层变量 | 不能用 `/xbdelvar`，改用酒馆自带的 `/flushvar 名称` |

建新变量时把规则一起带上最省事：

```text
/xbsetvar key="$free 人物状态" {"金币": 0}
/xbsetvar 人物状态.地点 森林
/xbsetvar key="$list 背包" []
/xbpushvar 背包 苹果
```

注意 `/xbsetvar` 写对象或列表时会整个替换原值，给已有变量补规则前先确认里面的内容可以覆盖。

不勾选 `变量管理` 时没有这些限制：`/xbsetvar` 会自动创建不存在的中间层，`/xbdelvar 变量名` 会清空整个变量。

### 给变量加规则

`/xbsetvar` 可以在路径前加 `$` 开头的规则（需要勾选 `变量管理`），规则先生效，再写入值：

```text
/xbsetvar key="$range=[0,100] 好感度" 50
/xbsetvar 姓名 苏晚
/xbsetvar key="$ro 姓名"
```

`$ro` 要单独一条、放在赋值之后：写在同一条里时，只读先生效，值就写不进去了。

| 规则 | 意思 |
| --- | --- |
| `$ro` | 只读，之后不能改 |
| `$range=[最小,最大]`、`$min=`、`$max=` | 数字范围，超出会被拉回范围内 |
| `$step=n` | 每次最多变化 n |
| `$enum={甲;乙;丙}` | 文字只能是这几个值之一 |
| `$match=/正则/` | 文字必须匹配这个正则 |
| `$ext` | 允许在这个对象下新增键 |
| `$prune` | 允许删除这个对象下的键 |
| `$free` | 新增、删除键都允许 |
| `$grow`、`$shrink`、`$list` | 允许列表变长、变短，或两者都行 |

规则跟着当前聊天保存，对 1.0 的 `<plot-log>` 同样有效（`<plot-log>` 里也可以在键名前写这些规则）。2.0 有自己的规则写法，见[变量 2.0 的约束](variables-v2.md#四约束)；3.0 的规则写在卡上的规则文件里。

## 读取变量的宏

宏可以放进世界书、预设、角色描述，发给 AI 时会替换成变量当前的值。

也可以写在消息正文里，但要注意：消息显示后，宏会被替换成当时的值并**写回这条消息**，之后变量再变，这条消息里的数字不会跟着变。

| 宏 | 显示成 | 适合 |
| --- | --- | --- |
| `{{xbgetvar::路径}}` | 文字、数字原样；对象和列表是一行 JSON | 插入一个值，或放进 JSON 模板 |
| `{{xbgetvar_yaml::路径}}` | 多行 YAML | 让 AI 读整份状态，比 JSON 好读 |
| `{{xbgetvar_yaml_idx::路径}}` | 多行 YAML，列表每项后面标 `# [0]`、`# [1]` | 需要 AI 按下标修改列表项时 |

例子：

```text
<当前状态>
{{xbgetvar_yaml::人物状态}}
</当前状态>
主角现在有 {{xbgetvar::人物状态.金币}} 枚金币。
```

- 路径写法和命令相同。路径不存在时替换成空，不报错。
- 酒馆自带的 `{{getvar::名称}}` 只能读整个变量；要读里面某一项，用 `{{xbgetvar::…}}`。


## 条件规则（varevent）

条件规则让世界书或预设里的一段文字按变量取值变化：好感低时写“她很冷淡”，好感高时写“她愿意和你独处”。AI 只看到命中的那一档，看不到条件和其他档。三种模式都能用。

### 写法

把各档写进一个 `<varevent>` 块，放进世界书条目或预设条目：

```text
<varevent>
[event.冷淡]
display: "莉娜对你很冷淡。"
[event.亲近]
condition: var(`人物状态.好感度`) >= val(`40`)
display: "莉娜愿意和你单独相处。"
[event.热恋]
condition: var(`人物状态.好感度`) >= val(`80`) && var(`人物状态.地点`) == val(`花园`)
display: "莉娜在花园等你。"
js_execute: "await STscript('/echo 触发了热恋事件')"
</varevent>
```

| 字段 | 意思 |
| --- | --- |
| `[event.名称]` | 一档的开头，名称自己取，不能含换行和 `]` |
| `condition` | 条件；不写表示总是成立 |
| `display` | 命中时放进提示词的文字 |
| `js_execute` | 命中时执行的脚本（可选） |

### 怎么选中一档

- **从下往上找**，选第一个条件成立、并且有 `display` 或 `js_execute` 的档。所以没有条件的兜底档放最上面，越严格的放越下面。
- 整个 `<varevent>…</varevent>` 块被替换成选中档的 `display`；一档都没命中就替换成空。
- 一个条目里可以有多个 `<varevent>` 块，各自独立选。

### 条件怎么写

| 写法 | 意思 |
| --- | --- |
| ``var(`路径`)`` | 读变量，路径写法同上 |
| ``val(`值`)`` | 一个固定值 |
| `==`、`!=` | 等于、不等于 |
| `>`、`>=`、`<`、`<=` | 比大小 |
| `&&`、`\|\|`、`!`、括号 | 并且、或者、取反、分组 |

比较规则：

- 两边都像数字（如 `40`、`3.5`、`1e3`）时按数字比；否则按文字比。
- 变量不存在或为 `null` 时，所有比大小都不成立，不会当成 0。
- 空字符串和“不存在”不一样。
- 读到对象或列表时，按它的 JSON 文字来比。

### 脚本什么时候执行

- 选中的 `display` 在发请求时就放进提示词；同一档的 `js_execute` **等 AI 这次回复成功完成后**才执行。
- 普通发送、重新生成、新 swipe、继续都这样处理。中途停止、生成失败、切换聊天、编辑或删除这条回复，还没执行的脚本会被取消。
- 提示词预览、后台的计数请求不会执行脚本。
- 脚本里可以用 `getVar(名称)`、`setVar(名称, 值)`、`STscript('/命令')` 和 `ctx`（酒馆上下文）。
- 脚本直接在酒馆页面里运行，不是沙箱。只用你信任的卡。
- 2.0、3.0 管理的变量不要在脚本里直接改，它们不会被记进楼层历史，删消息、切 swipe 时无法恢复。

### 用可视化编辑器

不想手写也可以用编辑器：

1. 打开酒馆的世界书，展开要编辑的条目。
2. 条目内容框上方、“最大化”按钮旁边有一个尺子图标（`条件规则编辑器`），点它。
3. 编辑器里：
   - 顶部 `组 1`、`组 2`… 对应条目里的每个 `<varevent>` 块，`+组`、`-组` 增删。
   - `添加事件` 新增一档；点“事件 #1”上的名称可以改名，`✕` 删除这一档。
   - “执行条件”里点 `添加条件小组`、`添加条件`。每行选 `比较值` 或 `比较变量`，填变量名、选比较方式（等于、大于或等于……）、填值。小组之间、行之间用“和/或”连接。
   - “将显示世界书内容（可选）”填 `display`。
   - “将执行stscript命令或JS代码（可选）”填 `js_execute`；点 `常用st控制` 可以用表单拼出改变量、开关世界书条目、运行快速回复的命令。
4. 点 `确认` 写回条目内容。

手写的复杂条件（编辑器表达不了的）会以源码形式显示，可以直接改，不会被删掉。条件写错时，保存会提示“请先修正标出的条件，已填写的内容会保留。”并标出出错的档。

### 出错时会看到什么

| 提示 | 原因 | 怎么办 |
| --- | --- | --- |
| 条件有误（事件名）：… | 条件不是合法表达式 | 检查括号、引号；这一档按“不成立”处理，其他档照常 |
| 事件脚本执行失败（事件名）：… | `js_execute` 运行出错 | 打开浏览器控制台看详细错误 |
| 未找到内容输入框，请先展开该条目的编辑抽屉 | 打开编辑器时条目没展开 | 先展开条目再点尺子图标 |

### bump 数值映射（1.0）

编辑器底部的 `bump数值映射设置` 用于 1.0 模式：把 AI 在 `bump` 里写的词换成数字，例如“略微提升”→ `5`、“大幅下降”→ `-20`。可以对所有变量生效，也可以只对某个变量生效；短语也可以写成 `/正则/`。设置保存在当前角色卡上，保存后提示“Bump 映射已保存到角色卡”。

## 常见问题

### 变量没有变化

1. 确认 `变量管理` 已勾选，并且模式和卡要求的一致。1.0 的卡选 2.0 不会生效，反之亦然。
2. 用变量面板或 `/xbgetvar` 看实际值。
3. 2.0、3.0 的排查方法见各自页面。

### 宏显示成空白

路径不存在或写错了。用变量面板长按复制宏，路径一定是对的。

### 世界书里的 `<varevent>` 原样发给了 AI

确认小白X总开关已打开。条件规则不依赖 `变量管理` 勾选框，但需要小白X在运行。
